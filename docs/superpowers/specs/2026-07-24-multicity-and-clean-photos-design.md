# Мультигород (СПб/МСК) + чистые фото товаров — дизайн

**Дата:** 2026-07-24
**Статус:** согласовано, готово к плану реализации
**Контекст:** созвон с Виталием зафиксировал: цена = РРЦ; городов ровно два — СПб и МСК;
диски надо включить (отдельной выгрузкой); на вотермарк «пофик»; подбор по авто — пауза
(Виталик даст базу). Ссылку на «живые фото» дал отдельным XML-фидом (Avito-формат).

Две связанные фичи в одной спеке:
1. Переключение города на сайте (СПб/МСК) с city-aware каталогом.
2. Чистое фото товара (без вотермарка) как основное — из Avito-фида.

---

## 1. Решения, уже принятые (не переоткрывать)

- **Механика города:** кука `city` на одном домене (стиль DNS/М.Видео/Ozon). Без поддоменов,
  без префикса пути, без авто-геолокации по IP и без модалки первого захода (в бэклог).
- **Данные по городам:** и цена, и остаток различаются по городу. Товар без наличия в
  выбранном городе — **скрыт** из листинга (не «под заказ» — это упрощение на потом).
- **Цена:** РРЦ (минимальная `recommended_retail_price` среди складов города; фолбэк — мин.
  `minimal_internet_price`). Логика фолбэка — как сейчас, но считается **по каждому городу**.
- **Фото:** вариант А — берём чистое фото из Avito-фида как основное. Галереи нет
  (SelectTyres отдаёт одно фото на товар — подтверждено на двух XML-фидах).

## 2. Что выяснено про источники данных

### 2.1 Avito-фид «живых фото» (XML)
- Формат `<Ads target="Avito.ru">` → `<Ad>` с `<Id>` = `code` товара (совпадает с основным фидом).
- **Одно** `<Image url="…"/>` на товар (у ~125 из 14696 фото нет). URL прямой статический:
  `https://lk.selectyre.ru/media/tires/big/<brand>/<model>_<id>.png` — **без токена, без вотермарка**.
- Сравнение с основным фидом (код `t499558`): та же картинка 800×800, тот же ракурс; основной
  фид отдаёт её через `photo-processor/get-photo/<JWT>/` **с вотермарком «TIRE STOCK»**, Avito —
  чистую напрямую. Вывод: Avito-фид = источник чистых кешируемых URL, а не многоракурсных фото.
- В фиде есть `ProductType`: `Легковые шины` (8842) и `Диски` (5854) — фото дисков уже есть,
  пригодятся, когда включат выгрузку дисков с ценами/остатками.

### 2.2 Основной JSON-фид (ассортимент + остатки)
- На момент написания URL из `deploy/.env` отдаёт **403 AccessDenied** (объект протух/очищен),
  тогда как свежесгенерированные XML-фиды с того же хоста отдают 200.
- **Ссылки на выгрузки не постоянные — ротируются/протухают.**
  - Разблокировка сейчас: Виталий перегенерирует «Единую выгрузку» в кабинете → свежий URL в `.env`.
  - Вопрос к поддержке SelectTyres (в TODO): есть ли постоянная ссылка / API-эндпоинт, или каждый
    экспорт = новый URL. Если ротируется — синкеру нужен способ всегда брать свежую.
- **Реальные `stock_name` московских складов пока неизвестны** (нужен живой фид). MSK-фильтр
  делаем конфигурируемым (env), дефолт-догадка `msk,moskva,moscow`, **сверить с живым фидом**.

## 3. Модель данных (БД, миграция 0004)

Город-независимые атрибуты остаются в `products`; цена/остаток выносятся в отдельную таблицу
по городам.

```sql
-- 0004_multicity_photos.up.sql
ALTER TABLE products ADD COLUMN image_clean_url TEXT NOT NULL DEFAULT '';

CREATE TABLE product_offers (
    product_code TEXT   NOT NULL,
    city         TEXT   NOT NULL,           -- 'spb' | 'msk'
    price        BIGINT NOT NULL,           -- копейки/рубли — как в products.price сейчас
    stock        INT    NOT NULL,
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (product_code, city)
);
CREATE INDEX product_offers_city_stock_idx ON product_offers (city, stock);
```

- `products.price` / `products.stock` — legacy-колонки. На переходный период оставляем
  (мок/старые запросы), но каталог city-aware читает из `product_offers`. Отдельной задачей
  можно будет дропнуть после переключения всех потребителей.
- «Нет в городе» = нет строки в `product_offers` для `(code, city)`.

## 4. Синк (два воркера)

### 4.1 JSON-синкер (правка существующего `integrations/selecttyres`)
- `Config`: вместо одного `StockFilter []string` — **карта городов** `CityStockFilters map[string][]string`
  (напр. `{"spb": [...], "msk": [...]}`), заполняется из env.
- `mapTire` → возвращает товар + срез предложений по городам: для каждого города, где нашлись
  склады, считает `price` (мин. РРЦ, фолбэк мин. интернет) и `stock` (сумма). Товар сохраняем,
  если есть предложения **хотя бы в одном** городе.
- `catalog.SyncProduct`: убрать плоские `Price/Stock`, добавить `Offers []CityOffer{City, Price, Stock}`.
- Синкер: upsert `products` (без цены/остатка) + upsert строк `product_offers`; строки городов,
  которых в этом проходе нет, — удалять/обнулять (аналог текущего `ZeroStaleBefore`, но по offers).

### 4.2 Новый Avito-фото-синкер (`integrations/selecttyres` или подпакет `photos`)
- Отдельный `Client` со стриминговым `encoding/xml` декодером по `<Ad>`.
- Для каждого `<Ad>`: `code = <Id>`, `url = первый <Image url>`; если url непустой →
  `UPDATE products SET image_clean_url = $url WHERE code = $code`.
- Свой env `SELECTYRES_PHOTO_FEED_URL`; интервал — общий `SELECTYRES_SYNC_INTERVAL`.
- Запускается отдельной горутиной из `main.go` рядом с JSON-синкером.

## 5. Выбор города (Next)

- Кука `city` (`spb`|`msk`), дефолт `spb`. Читается на сервере (`cookies()` async, React 19).
- **Переключатель в шапке** (клиентский компонент) в топбаре, где сейчас адрес
  «Санкт-Петербург, Зотовский пр. 11». Меняет город → ставит куку → `router.refresh()`.
  Адрес и телефон в топбаре переключаются по городу (данные городов — статическая карта в web).
- Хелпер `getCity()` (сервер) читает куку с валидацией (`spb`|`msk`, иначе дефолт).

## 7. Фото товара (вариант А)

- Эффективное фото = `image_clean_url`, если непустое, иначе `image_url` (токенный фолбэк).
  Вычисляем на бэкенде (в SQL `COALESCE(NULLIF(image_clean_url,''), image_url)`), в API поле
  остаётся `image_url` = «то, что показывать». Фронт не меняет логику отображения.
- `next.config.ts`: `remotePatterns` уже допускает `lk.selectyre.ru` — прямой хост тот же, ок.
- Галереи нет. Многоракурсные «живые фото» — будущая задача (загрузка через админку), если у
  Виталия есть свои снимки. В вопросы Виталию.
