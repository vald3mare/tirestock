## Карта системы
```
SelectTyres ──(товары/цены/остатки, авто-база подбора)──▶ [синк] ──▶ Новая витрина (read-модель)
                                                                        │            ▲
                                                            заказ, заявки, звонки    │ контент
                                                                        ▼            │
                                                                  tradesk.ru      Новая админка
                                                                  (Yii2, учёт)    (Виталий, Софья,
                                                                        ▼           сотрудники)
                                                              управляющий «на земле»
Битрикс: старый монолит (витрина+контент+транзит). Доживает на старом домене до переключения.
Новый сайт наследует его URL-структуру. Тест — на отдельном домене, сравнение со старым.
```

## Компоненты
- **tirestock.ru (Битрикс)** — старая витрина + контентная админка + транзит заказов.
  ~4000 визитов/день органики, ~60 городских поддоменов (механика не выяснена).
  Доступ: логин/пароль не подходит — добыть новый у Виталия. Внутри искать: модуль/крон
  обмена с SelectTyres, обработчики отправки заказов, список инфоблоков (= скоуп новой
  админки), устройство поддоменов, структуру URL.
- **SelectTyres** — отраслевая платформа: каталог, цены, остатки («автоматическое
  обновление» со слов Виталия), есть база подбора по авто (использовать для таба «По авто»).
  Механизм отдачи (API/фид/модуль) — не выяснен.
- **tradesk.ru** — самописная учётная CRM на Yii2 (server-rendered, bootstrap+jquery,
  site.css?ver=24 → правился). Разделы: Продажи, Доставка, Сервис, Заявки, Хранение,
  Обратный звонок, Возвраты, Обзвон, Учёт. Это НЕ «просто статусы заказов» — полный
  операционный контур, включая учёт хранения (приоритетный сервис бизнеса).
  Автор — предыдущий разработчик, связи нет (искать через Виталия!). Публичного API нет.
- **Новая витрина** — по макету Figma. Слой данных через репозиторий-интерфейс
  (мок → синк-база позже). Эквайринг — новое требование (уточнить юрлицо-подписанта).
- **Новая админка** — минимальная CMS: страницы, тексты, баннеры, SEO-мета, оверрайды
  товаров (скрыть/бейдж). НЕ дублирует tradesk (заказы) и SelectTyres (товары).

## Развёртывание (контейнеры и адреса)
Локально/на VPS поднимается через `deploy/docker-compose.yml`. На машинах, где firewall
режет межконтейнерный трафик, добавляется overlay `docker-compose.hostnet-workaround.yml`
(сервисы ходят друг к другу через published-порты хоста и `host.docker.internal`).

| Контейнер | Адрес (host) | Что внутри | Зависит от |
|---|---|---|---|
| `deploy-postgres-1` | `localhost:5432` | PostgreSQL: read-модель, заказы, outbox, контент | — |
| `deploy-api-1` | `localhost:8080` | Go: API `/api/v1/*` + outbox-воркер (в одном процессе) | postgres |
| `deploy-web-1` | `localhost:3000` | Next.js (прод-сборка витрины+админки) | api |

Тома: `pgdata` (БД) и `web-image-cache` — кэш пережатых фото товаров
(`/app/.next/cache/images`). Кэш вынесен в том осознанно: он переживает пересборку
образа (после деплоя фото не оптимизируются заново) и не растёт в слое контейнера.
Размер ограничен `images.maximumDiskCacheSize` (512 МБ, вытеснение по LRU), срок
жизни — `minimumCacheTTL` 31 день вместо дефолтных 60 секунд: фото приходят из фида
и меняются редко, пережимать их каждую минуту незачем. Списки `deviceSizes`/
`imageSizes` урезаны под реальные слоты вёрстки (макс. 544px), иначе Next держал бы
по 16 вариантов на каждое из 6,5к фото.

Внутренние health: api → `GET /api/v1/health` (пингует БД). Воркер доставки — горутина
внутри `deploy-api-1`, отдельного контейнера нет. Env доставки — в `deploy/.env`
(`OLDSITE_BASE_URL` / `TRADESK_*`), см. ниже.

### Гейт индексации (SEO — священная корова)
Сайт запускается на тестовом домене рядом с живым `tirestock.ru`; попасть в индекс он
не должен (дубли утянут выдачу старого сайта). Механизм — **fail-safe** по env
`SITE_INDEXABLE` (`web/lib/site-env.ts`): индексация разрешена ТОЛЬКО при явном
`SITE_INDEXABLE=true`, любое другое значение/отсутствие → сайт закрыт. Забытый env
прячет сайт, а не светит его. Два уровня: `app/robots.ts` отдаёт `Disallow: /` вне
боевого домена, а `middleware.ts` вешает `X-Robots-Tag: noindex, nofollow` на все
ответы (сильнее robots.txt — Google убирает уже обойдённые страницы). На боевом домене
`SITE_INDEXABLE=true` открывает сайт, кроме `/admin`, `/cart`, `/dev`.

## Доставка заявок и заказов в tradesk (реализация)
Заявка/звонок/заказ пишется в `outbox` в одной транзакции с приёмом; воркер с ретраями
доставляет наружу (заказ никогда не теряется). Ответ приёмника сохраняется в
`outbox.result` — для заказа это НОМЕР записи в tradesk, его показывает админка.
Адаптеры за интерфейсом `orders.OrderDelivery`, цель выбирается по env.

- **Основной путь — прямой tradesk** (`TRADESK_BASE_URL`, пакет `integrations/tradesk`).
  Контракт вскрыт 11.08.2026 из исходников `/ajax/*.php` (docs/OLDSITE_AJAX.md).
  Приёмники публичные — без авторизации, сессии и CSRF:
  - обратный звонок: `GET /data/backcall?phone=&comment=` (поля имени нет — адаптер
    подмешивает имя в начало `comment`);
  - заказ: `GET /api/addorder?phone=&name=&comment=&qty=&product=&code=&price=&city=&type=`
    — ОДНА позиция на вызов (многопозиционный заказ уходит N вызовами), ответ — номер
    заказа в кавычках либо строка `error` (её считаем отказом);
  - заявка формы услуги: `POST /api/request` (form) с полями `name/phone/extra/type/site`.
  Админ-контур Yii2 (логин + CSRF) в клиенте остался, но доставкой НЕ используется.
- **Аварийный мост через Битрикс** (`OLDSITE_BASE_URL`, пакет `integrations/oldsite`) —
  POST на `/ajax/call.php`, `/ajax/order.php`, `/ajax/request.php`. Битрикс там тонкий
  прокси в те же приёмники. Включать, только если прямой контур недоступен: клиент
  пишет WARN в лог. Зависит от живого Битрикса.
- **Мок** (`integrations/mock`) — если ни один env не задан (дев-стенд по умолчанию,
  чтобы разработка не плодила реальные записи в учётке).

**Локальный стенд, стреляющий в боевой tradesk.** Для сквозной проверки руками
в `deploy/.env` задаётся `TRADESK_BASE_URL=http://tradesk.ru`. Тогда КАЖДАЯ форма
на localhost создаёт реальную запись в учётке заказчика, удалить её мы не можем —
поэтому вместе с адресом задаётся `DELIVERY_TEST_MARK`: пометка приписывается к
комментарию каждой заявки и заказа (`orders.Service.WithCommentPrefix`), менеджер
видит тестовую запись и не тратит звонок. На проде пометка пустая.

Приоритет выбора в `main.go`: TRADESK → OLDSITE → мок.

⚠️ Пространства кодов не совпадают: в `code` старый сайт слал код своего магазина
(«Код товара» на карточке, напр. 99302), у нас код SelectTyres (`t668559`). Карты
соответствия нет — адаптер шлёт наш код и дублирует опознание в `comment`.

## Дизайн контрактов API («работает как часы»)
Принципы, чтобы запрос пользователя не «отвалился молча»:
1. **Публичное API — единый источник истины OpenAPI.** `api/openapi.yaml` → генерация
   TS-типов (`npm run gen:api` → `web/lib/api/schema.d.ts`). Фронт витрины использует
   только сгенерированные типы — рассинхрон Go↔TS исключён by design.
2. **Инвариант non-nil.** Любое `required`-поле-массив в ответе ВСЕГДА сериализуется
   как `[]`, не `null` (иначе клиент падает на `.length`). Go-хендлеры инициализируют
   слайсы `[]T{}`; места с `array_agg` (может вернуть NULL) страхуются явно
   (`DBSource.Facets`, `orderstatus`). Фронт дополнительно null-safe (второй рубеж).
3. **Единый формат ошибок** — `httpx.Error` (`{error:{code,message}}`); детали в лог,
   клиенту generic-сообщение. Валидация входа → 400 `validation_failed`, не 500.
4. **Контрактный smoke-тест** — `deploy/smoke-api.sh` прогоняет все публичные
   эндпоинты (коды + обязательные поля + граничные случаи: плохой city/width/slug →
   400/404, не 500). Прогонять после правок API и в CI.
5. **Admin API** пока НЕ в OpenAPI — типы в `web/lib/api/admin.ts` ведутся вручную
   в соответствии с Go-структурами (сейчас синхронны). Кандидат на вынос в OpenAPI,
   когда админка стабилизируется; до тех пор — держать поля в паре Go↔TS синхронно.

## Открытые вопросы (влияют на смету интеграции)
1. Как SelectTyres отдаёт данные — ВСКРЫТО по доке (docs.selectyre.ru). Модель — не живой REST,
   а **файлы-выгрузки (фиды)**, настраиваются в кабинете с периодичностью обновления, форматы
   JSON/XML/CSV. Два фида, связь по полю `code`:
   - **Ассортимент** (структура каталога, меняется редко): `metainfo` + `tires[]`/`wheels[]`.
     Шина: `code`, `p_full_name`, `p_brand`, `p_model`, `p_width`(мм), `p_height`(профиль),
     `p_diameter`(дюймы), `p_season`(строка «Зимняя»/«Летняя»/…), `p_thorn`(bool), `p_runflat`(bool),
     `p_photo`. Диск: + `p_type`, `p_pcd`, `p_et`, `p_dia`.
   - **Остатки+цены** (меняется часто): `code`, `price`, `wholesale_price`, `quantity`,
     `stock_name`/`stock_name_ru` (ПО СКЛАДАМ — несколько строк на `code`),
     `recommended_retail_price`, `minimal_internet_price`, `delivery_time`, `sale`.
   Цены — рубли (наценка задаётся профилями в кабинете). «Всего товаров» = длина `tires`.
   Наш синк: воркер (time.Ticker) качает оба фида → upsert в read-модель `products` (миграция 0001),
   `CatalogSource` становится DB-адаптером (пакет `integrations/selecttyres`), мок уходит.
   `stock_name` несёт географию (напр. `..._vladivostok`) — вероятная завязка мультигорода (см. №8).
   ОСТАЁТСЯ у Виталия/кабинета: реальные URL настроенных файлов (+ токен в URL?), настроены ли уже
   (старый сайт тянет через «Модуль для Битрикс») или создавать через support@selectyre.ru;
   период обновления; какой склад/город брать по умолчанию.
2. Как заказ/заявка попадает из Битрикса в tradesk — **ВСКРЫТО 11.08.2026** (исходники
   `/ajax/*.php` прочитаны через админку Битрикса, Контент → Файлы и папки):
   ```php

   if ($_POST) {
       file_get_contents('http://tradesk.ru/data/backcall?phone=' . urlencode($_POST['phone'])
                          . '&comment=' . urlencode($_POST['comment']));
   }
   ```
   То есть Битрикс — **тонкий прокси**: обычный серверный GET в публичное пространство
   `tradesk.ru/data/<сущность>`, БЕЗ авторизации, сессии и CSRF. Общей БД и крона нет.
   Наш прямой адаптер (`integrations/tradesk`) переписан на этот контракт: заявки можно
   слать в tradesk напрямую, мост через Битрикс для звонков больше не нужен.
   Замечено также `/ajax/auth.php` → `GET http://tradesk.ru/api/login?phone=` (есть и
   namespace `/api/`; сам файл нерабочий — синтаксическая ошибка в `switch`, не исполнялся).

   ОДНА позиция на вызов, ответ — номер заказа в кавычках либо `error`.
   ⚠️ Поле `code` там — код старого магазина (напр. 99302), у нас код SelectTyres

2a. **Битрикс выведен из цепочки (11.08.2026).** Приоритет доставки в `main.go`:

## Правила работы с чужим продом
Битрикс/tradesk — только read-only разведка под выданными доступами; ничего не сохранять
в настройках; тестовые записи — только помеченные и с предупреждением управляющего;
реальные заказы/клиентов не редактировать; перед записью — бэкап.
