## Карта системы
```
SelectTyres ──(товары/цены/остатки, авто-база подбора)──▶ [синк] ──▶ Новая витрина (read-модель)
                                                                        │            ▲
                                                            заказ, заявки, звонки    │ контент
                                                                        ▼            │
                                                                  tradesk.ru      Новая админка
                                                                  (Yii2, учёт)    (Виталий, Софья,
                                                                        ▼           сотрудники)
                                                              управляющий «на земле»
Битрикс: старый монолит (витрина+контент+транзит). Доживает на старом домене до переключения.
Новый сайт наследует его URL-структуру. Тест — на отдельном домене, сравнение со старым.
```

## Компоненты
- **tirestock.ru (Битрикс)** — старая витрина + контентная админка + транзит заказов.
  ~4000 визитов/день органики, ~60 городских поддоменов (механика не выяснена).
  Доступ: логин/пароль не подходит — добыть новый у Виталия. Внутри искать: модуль/крон
  обмена с SelectTyres, обработчики отправки заказов, список инфоблоков (= скоуп новой
  админки), устройство поддоменов, структуру URL.
- **SelectTyres** — отраслевая платформа: каталог, цены, остатки («автоматическое
  обновление» со слов Виталия), есть база подбора по авто (использовать для таба «По авто»).
  Механизм отдачи (API/фид/модуль) — не выяснен.
- **tradesk.ru** — самописная учётная CRM на Yii2 (server-rendered, bootstrap+jquery,
  site.css?ver=24 → правился). Разделы: Продажи, Доставка, Сервис, Заявки, Хранение,
  Обратный звонок, Возвраты, Обзвон, Учёт. Это НЕ «просто статусы заказов» — полный
  операционный контур, включая учёт хранения (приоритетный сервис бизнеса).
  Автор — предыдущий разработчик, связи нет (искать через Виталия!). Публичного API нет.
- **Новая витрина** — по макету Figma. Слой данных через репозиторий-интерфейс
  (мок → синк-база позже). Эквайринг — новое требование (уточнить юрлицо-подписанта).
- **Новая админка** — минимальная CMS: страницы, тексты, баннеры, SEO-мета, оверрайды
  товаров (скрыть/бейдж). НЕ дублирует tradesk (заказы) и SelectTyres (товары).

## Развёртывание (контейнеры и адреса)
Локально/на VPS поднимается через `deploy/docker-compose.yml`. На машинах, где firewall
режет межконтейнерный трафик, добавляется overlay `docker-compose.hostnet-workaround.yml`
(сервисы ходят друг к другу через published-порты хоста и `host.docker.internal`).

| Контейнер | Адрес (host) | Что внутри | Зависит от |
|---|---|---|---|
| `deploy-postgres-1` | `localhost:5432` | PostgreSQL: read-модель, заказы, outbox, контент | — |
| `deploy-api-1` | `localhost:8080` | Go: API `/api/v1/*` + outbox-воркер (в одном процессе) | postgres |
| `deploy-web-1` | `localhost:3000` | Next.js (прод-сборка витрины+админки) | api |

Внутренние health: api → `GET /api/v1/health` (пингует БД). Воркер доставки — горутина
внутри `deploy-api-1`, отдельного контейнера нет. Env доставки — в `deploy/.env`
(`OLDSITE_BASE_URL` / `TRADESK_*`), см. ниже.

## Доставка заявок в tradesk (реализация)
Заявка/звонок пишется в `outbox` в одной транзакции с приёмом; воркер с ретраями
доставляет наружу (заказ никогда не теряется). Цель доставки выбирается по env,
адаптеры за интерфейсом `orders.OrderDelivery`:

- **Вариант 1 — мост через старый сайт** (`OLDSITE_BASE_URL`, пакет `integrations/oldsite`).
  ВРЕМЕННЫЙ, на период параллельного запуска. Воркер POST-ит на публичные битриксовые
  обработчики — заявки капают в tradesk точно как со старого сайта. Контракт вскрыт из
  `tirestock.ru/js/script.js` (read-only), сайт на UTF-8, без авторизации/CSRF:
  - обратный звонок: `POST /ajax/call.php`, тело `phone=<>&comment=<>` (имени в форме нет —
    наш адаптер подмешивает имя в начало `comment`);
  - заявка (напр. покраска): `POST /ajax/request.php`, тело `name=<>&phone=<>&extra=<>&type=<>`.
  ⚠️ Зависит от живого Битрикса — переключить на Вариант 2 ДО его выключения.
- **Вариант 2 — прямой tradesk** (`TRADESK_*`, пакет `integrations/tradesk`, готов, не активен).
  Yii2-клиент: `GET /site/login` → CSRF из `<meta name="csrf-token">` → `POST` login,
  сессия в cookiejar (`_identity`/`PHPSESSID`/`_csrf`), релогин при протухании.
  БЛОКЕР: реальные имена полей приёмника неизвестны (в админке `backcall/create` → 404),
  берутся из исходника `call.php` (FTP старого хостинга) или у Виталия.
- **Мок** (`integrations/mock`) — если ни один env не задан.

Приоритет выбора в `main.go`: OLDSITE → TRADESK → мок.

## Открытые вопросы (влияют на смету интеграции)
1. Как SelectTyres отдаёт данные — ВСКРЫТО по доке (docs.selectyre.ru). Модель — не живой REST,
   а **файлы-выгрузки (фиды)**, настраиваются в кабинете с периодичностью обновления, форматы
   JSON/XML/CSV. Два фида, связь по полю `code`:
   - **Ассортимент** (структура каталога, меняется редко): `metainfo` + `tires[]`/`wheels[]`.
     Шина: `code`, `p_full_name`, `p_brand`, `p_model`, `p_width`(мм), `p_height`(профиль),
     `p_diameter`(дюймы), `p_season`(строка «Зимняя»/«Летняя»/…), `p_thorn`(bool), `p_runflat`(bool),
     `p_photo`. Диск: + `p_type`, `p_pcd`, `p_et`, `p_dia`.
   - **Остатки+цены** (меняется часто): `code`, `price`, `wholesale_price`, `quantity`,
     `stock_name`/`stock_name_ru` (ПО СКЛАДАМ — несколько строк на `code`),
     `recommended_retail_price`, `minimal_internet_price`, `delivery_time`, `sale`.
   Цены — рубли (наценка задаётся профилями в кабинете). «Всего товаров» = длина `tires`.
   Наш синк: воркер (time.Ticker) качает оба фида → upsert в read-модель `products` (миграция 0001),
   `CatalogSource` становится DB-адаптером (пакет `integrations/selecttyres`), мок уходит.
   `stock_name` несёт географию (напр. `..._vladivostok`) — вероятная завязка мультигорода (см. №8).
   ОСТАЁТСЯ у Виталия/кабинета: реальные URL настроенных файлов (+ токен в URL?), настроены ли уже
   (старый сайт тянет через «Модуль для Битрикс») или создавать через support@selectyre.ru;
   период обновления; какой склад/город брать по умолчанию.
2. Как заказ/заявка попадает из Битрикса в tradesk. ЧАСТИЧНО: фронт старого сайта шлёт на
   битриксовые обработчики `/ajax/call.php` и `/ajax/request.php`; они (серверный код,
   чёрный ящик) доводят до tradesk. КАК именно доводят (прямой вызов tradesk / общая БД /
   крон) — не вскрыто снаружи. Нужен исходник `call.php` (FTP старого хостинга) или Виталий.
3. Контракт заявок ВСКРЫТ (см. «Доставка заявок»): звонок — `phone/comment` → `/ajax/call.php`;
   заявка — `name/phone/extra/type` → `/ajax/request.php`. Остаётся контракт tradesk-приёмника
   (за call.php) и контракт заказа/оформления (checkout старого сайта не вскрыт).
   Админка tradesk: статусы звонка `new/process/complete`, смена — `POST /backcall/change`
   (`Backcall[backcall_status]`+`backcall_id`); create-действия в админке нет.
4. Есть ли у tradesk внутренние AJAX-эндпоинты (DevTools → XHR при действиях; main.js
   почитать — адреса могут быть текстом). Yii2 CSRF стандартный (meta _csrf).
5. Хостинг tradesk: если общий с сайтом — возможен доступ к коду (Yii самодокументируется
   структурой controllers/models) и к БД. Спросить Виталия.
6. БЭКАПЫ tradesk — проверить/снять дамп ДО любых записывающих тестов. Система без
   поддержки и без бэкапов = главный риск проекта.
7. Контакт автора tradesk — запросить у Виталия повторно (час созвона économит недели).
8. 60 поддоменов: мультисайтовость? Различаются ли цены/остатки по городам?
9. Эквайринг: провайдер и юрлицо-подписант (Виталий не в РФ).

## Правила работы с чужим продом
Битрикс/tradesk — только read-only разведка под выданными доступами; ничего не сохранять
в настройках; тестовые записи — только помеченные и с предупреждением управляющего;
реальные заказы/клиентов не редактировать; перед записью — бэкап.
